## The diagnostic chain (the part worth remembering)

> The single most important lesson of this session: **a bug that
> looks like one class of problem can be a completely different
> class of problem in disguise**, and the wrong diagnosis will keep
> propagating itself until you confirm a load-bearing assumption
> from outside the system.

### Symptoms

The E1 work bumped `code-reviewer.md`'s frontmatter to `model: sonnet`
and added a CRITICAL OUTPUT CONTRACT section requiring a specific
envelope format and `pe gate parse` self-validation. **Three
successive live-test invocations of the agent showed:**

1. Agent self-reported `model_used: claude-haiku-4-5-20251001` (not Sonnet).
2. Envelope shape was improvised. Pass 1 had wrong `rule` format; pass 2
   regressed further to plain ` ```json ` fence with banned field
   names.
3. The CRITICAL OUTPUT CONTRACT section had no apparent effect.

### Wrong diagnosis (cost ~2 hours of E1.a tightening)

> "The `model:` frontmatter must not be honored by Claude Code's
> subagent runtime. Pure prompt engineering can't constrain agent
> output shape. We need the agent to self-validate via Bash."

This LED to a structurally good fix (E1.a self-validation step) but
based on a wrong premise. The self-validation step DID make envelope
validity tier-independent — pass 3 produced a clean envelope from
**Haiku**. That was the win. But the "frontmatter must not be
honored" inference was wrong.

### What forced the re-diagnosis

The operator-required E1.b investigation: "Investigate empirically
BEFORE rolling out the E1.1 mechanical pattern to 4 more agents."

Within 5 minutes of starting E1.b:

```bash
ls -lH ~/Documents/8Colors/8CStudio/.claude/agents/code-reviewer.md
# → No such file or directory

ls -lH ~/.claude/agents/code-reviewer.md
# → -rw-r--r--  1 sanishsasikumar  staff  10922 May 22 14:03

head -5 ~/.claude/agents/code-reviewer.md
# → model: haiku
```

**Claude Code was reading a completely different file than the one I
was editing.** The engine repo's `agents/code-reviewer.md` had `model:
sonnet` + full E1 contract. The file Claude Code actually resolved
was `~/.claude/agents/code-reviewer.md` — a regular file from
2026-05-22, predating the engine, with `model: haiku` and zero contract.

The official docs settled it: project-local symlinks win over user-global
regular files; user-global wins when project-local is absent.

### Real root cause

`pe install` was last run on 8CStudio at engine v0.1 when only 3
agents existed. The other 11 engine agents — including
`code-reviewer` — were never symlinked project-local. They fell
through to user-global regular files that pre-dated the engine and
never updated.

**Every E1 edit landed in a file Claude Code never read.**

### The fix and the green check (E1.c)

```bash
pe install ~/Documents/8Colors/8CStudio
# → 14 agents symlinked → 8CStudio/.claude/agents/
```

Then re-invoked `code-reviewer` on the same fixture. **Same session.
No restart.** Result:

| Metric | Pre-E1.c | Post-E1.c |
|---|---|---|
| `model_used` self-report | `claude-haiku-4-5-20251001` | **`claude-sonnet-4-6`** |
| Fence info-string | varied | `json gate-envelope` ✓ |
| Envelope schema | failed | passed ✓ |
| Self-validation Bash calls | 0 | 10 (real `pe gate parse` invocation) |
| Standalone `pe gate parse` exit | 4 (schema error) | 1 (correct FAIL worker_quality) |
| Cross-check section | absent | printed with literal values |

This single before/after is the green-check artifact. It proves
three things that were all in doubt:

1. **`model:` frontmatter IS honored** at runtime.
2. **Project-local DOES override user-global** per docs precedence.
3. **Subagent definitions are re-read per-invocation** — no session
   restart needed.

The session also locked in a useful auxiliary finding: of 10
user-global files that overlap with current master engine, **only
`architect.md` actually differs**. Suggests the eventual cleanup
audit will be a single-file judgment call, not 13.

## What's now structurally true

1. **Tiered routing is real at runtime.** Phase 3's escalation ladder
   can route on tier with confidence; `model: sonnet` in frontmatter
   actually serves Sonnet.
2. **Envelope validity is self-enforcing.** Each gate agent runs
   `pe gate parse` against its own draft before emission. Schema-invalid
   envelopes can't leave the agent.
3. **The propagation gap is self-diagnosable.** Beta testers see the
   warning at `pe install` time and the diagnostic at `pe doctor`
   time. They won't debug it from scratch like we did.
4. **Three engine commits hardened by code-review pass**. PR #1 had
   one code-reviewer self-review pass (PASS, 1 LOW intentional);
   PR #2 had a clean code-reviewer pass (PASS, 0 findings); PRs #3
   and #4 are doc-only or smoke-tested by-hand.
